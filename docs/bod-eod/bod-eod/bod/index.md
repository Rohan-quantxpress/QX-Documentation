# BOD (Beginning of Day) Process

## Overview

The **Beginning of Day (BOD)** process is the workflow used to prepare the system for the new trading day.

BOD brings together the required processes that need to be completed before normal trading operations begin. These processes may include downloading required data, preparing reference information, initializing system components, and performing the checks required for the trading environment.

The BOD workflow is controlled by the **Process Manager** and the processes registered in `process.json`.

```text
process.json
      ↓
BOD Process List
      ↓
BOD Scheduler
      ↓
Process Manager
      ↓
Execute BOD Processes
      ↓
Trading System Ready
```

BOD should be considered the **pre-trading preparation stage** of the system.

---

## Purpose of BOD

The main purpose of BOD is to ensure that the system has the required data and configuration before trading-related activities begin.

BOD is responsible for preparing the environment so that downstream applications can start their daily operations using the required information.

### Main Objectives

* Prepare the system for the new trading day
* Make required market and reference data available
* Execute the configured BOD processes in the required order
* Initialize required system information
* Ensure required files and dependencies are available
* Identify process failures before trading operations depend on them

---

## What Happens During BOD

The exact BOD activities depend on the processes registered in `process.json`.

At a high level, the workflow can include the following stages.

### 1. Configuration and Process Preparation

The Process Manager loads the configured BOD process definitions and determines which processes are active and should participate in the workflow.

```text
BOD Schedule
      ↓
Load BOD Configuration
      ↓
Identify Active Processes
      ↓
Prepare Execution Order
```

The configured process order is important because BOD processes may depend on the successful completion of earlier processes.

---

### 2. Data Preparation

BOD processes prepare the data required for the trading day.

Depending on the configured workflow, this can include:

* Downloading required market files
* Processing exchange/reference files
* Preparing required datasets
* Loading required information into system components

The purpose is to make the required daily data available to the applications that depend on it.

---

### 3. Data and File Processing

Downloaded or received files are processed by the relevant BOD scripts.

The process may involve:

```text
Input Files
     ↓
File Processing
     ↓
Validation / Transformation
     ↓
Required Data
```

Each process is responsible for its own specific operation, while Process Manager controls when that process is executed.

---

### 4. System Initialization

Some BOD processes prepare information required by other system components.

This may include initializing:

* Reference information
* Instrument-related information
* Redis-related data
* Runtime configuration
* Other daily system data

These activities help downstream services start with the required information.

---

### 5. Process Validation

Each BOD process reports its execution result to the Process Manager.

The workflow can therefore identify whether a process completed successfully or failed.

```text
Process Started
      ↓
Process Executes
      ↓
Success / Failure
```

If a required BOD process fails, the failure should be investigated before relying on the system for the next stage of operations.

---

# BOD Execution Flow

The overall BOD workflow can be represented as:

```text
Start
  ↓
BOD Schedule Triggered
  ↓
Load BOD Processes
  ↓
Check Active Processes
  ↓
Execute Processes in Order
  ↓
Process Completed?
  │
  ├── Yes → Continue to Next Process
  │
  └── No  → Handle Failure
                ↓
          Stop/Interrupt Flow
                ↓
          Alert / Investigation
  ↓
All Required Processes Completed
  ↓
BOD Completed
  ↓
System Ready for Next Stage
```

---

## Process Order

BOD processes are executed according to the order configured in `process.json`.

For example:

```text
Process 1
   ↓
Process 2
   ↓
Process 3
   ↓
Process 4
```

The order should be selected based on the operational dependency between processes.

For example, a process that requires data generated by an earlier process should not be placed before that process.

Therefore, whenever a new BOD process is added, its position in the BOD sequence should be reviewed carefully.

---

# BOD and Process Manager

Process Manager provides the execution framework for BOD.

It is responsible for:

* Scheduling the BOD workflow
* Reading the configured BOD process list
* Executing processes in the configured order
* Tracking process execution
* Handling process failures
* Updating runtime process information
* Providing process information to the monitoring/UI layer

The individual BOD scripts contain the logic for their specific task.

This separation keeps the system organized:

```text
Process Manager
     │
     │ Controls
     ↓
BOD Workflow
     │
     ├── Process 1
     ├── Process 2
     ├── Process 3
     └── Process 4
          │
          ↓
    Individual BOD Logic
```

---

# BOD Configuration

BOD execution is controlled through the BOD configuration in `process.json`.

The configuration determines:

* When BOD starts
* Which processes belong to BOD
* Which processes are active
* The execution order
* Where the scripts are located
* Which parameters are passed to the processes

Therefore, changes to the BOD workflow should normally be made through the configuration rather than by adding BOD-specific scheduling logic to `process_master.py`.

---

# What to Verify Before BOD

Before starting the BOD workflow, verify that:

* Required input files are available
* Required directories exist
* Process paths are correct
* Required services are available
* BOD processes are correctly registered
* Process order is correct
* Required processes are active

This helps identify configuration or environment problems before the BOD workflow begins.

---

# What to Do When BOD Fails

If a BOD process fails:

1. Identify the failed process from the UI or logs.
2. Check the process status and error information.
3. Verify the required input files.
4. Verify the configured application and input paths.
5. Check the process parameters.
6. Review the process logs.
7. Correct the underlying issue.
8. Restart the Process Manager if the configuration was changed.
9. Run the BOD workflow again.

The failed process should be understood and resolved before considering the BOD workflow successfully completed.

---

# BOD Completion

BOD is considered complete when the required configured processes have successfully finished their execution.

```text
BOD Started
     ↓
Required Processes Executed
     ↓
Processes Completed Successfully
     ↓
BOD Completed
     ↓
System Ready
```

The BOD workflow therefore acts as an important checkpoint between the **start of the trading day preparation** and the **normal operation of the trading system**.

---

## Key Takeaway

BOD is not a single script. It is a **sequence of configured processes managed by Process Manager**.

```text
process.json
     ↓
Defines BOD Processes
     ↓
BOD Scheduler
     ↓
Process Manager
     ↓
Execute Processes Sequentially
     ↓
Track Results
     ↓
BOD Completed
```

When working with BOD, the main things to understand are:

**Configuration → Process Order → Input Data → Execution → Status → Completion**

A correctly configured and successfully completed BOD workflow ensures that the required daily preparation activities have been completed before the system proceeds with its next operational stage.
